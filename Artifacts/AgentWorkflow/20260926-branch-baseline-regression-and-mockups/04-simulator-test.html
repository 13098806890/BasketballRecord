明确发现与风险

  1. 隔离基线首次启动因旧版 CloudKitManager 在 Simulator 调用 CKContainer.default() 崩溃；只在 baseline worktree 加了与当前 main 相同的 Simulator guard，未修改当前工作区。该问题应作为旧版环境缺陷保留记录。
  2. 旧版 Score 是空比赛状态，新版使用了 DEBUG fixture（108–97、每队 3 名球员、5 条事件）以覆盖数据密集布局，不能作为同状态像素对比，只能作为信息架构和功能集合对比。
  3. 当前 main 的源码 key 集合没有删除 Score action；发现的少量 removed key 是导航标题或 data range 文案被重命名为新 key，不是功能入口删除。
