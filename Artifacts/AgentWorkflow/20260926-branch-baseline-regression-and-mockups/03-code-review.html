代码审查 · UI 功能保留

审查范围：当前 main 工作区相对 main_free_pro 的 SwiftUI 页面差异，重点是比赛记分、比赛详情、球员详情、生涯和 Roster 功能。

通过项

  • GameView.swift 的 action key 集合与基线一致：四类投篮命中/未中、助攻、篮板分支、盖帽、抢断、犯规、失误、暂停、节次、换人、迟到、撤销、重做全部仍存在。
  • 原导航栏中的 New Game、Invite Collaboration、Save to History 已重新组合到 scorePageHeader；Reset/Finish 也保留并继续走原确认逻辑。
  • SavedGameDetailView 的球队球员列表仍保留号码、头像、球员名和 PTS/REB/AST/STL/BLK/TO；新增整行 NavigationLink，不改变数据来源。
  • PlayerProfileView 区分 fixedGame 与 career：比赛详情保留 Events，生涯详情不显示 Events；Career/Average/ELO/Choose Games 均保留。
  • 新增球队图标入口在 TeamEditorView；模型/导入解析兼容旧数据，缺少图标字段不会使解析失败。

需要关注但不是已确认缺陷

  • 少量旧本地化 key 被重命名，例如导航标题和 data range 文案；未发现对应按钮/状态逻辑被删除，但应在全部语言运行截图中验证文本不会回退。
  • 基线 main_free_pro 在 Simulator 上的 CloudKit 初始化会 SIGABRT；该差异已通过隔离 worktree guard 绕过以完成 UI 审计，不应把隔离 patch 当作当前 main 的新产品改动。
  • 现有 DataCompatibilityTests 中 Cloud-enabled game ID persistence 测试此前已知在 Simulator 直接写 NSUbiquitousKeyValueStore 时失败；本轮没有把它误报成 UI 回归。

结论

未发现“新 UI 删除旧功能”的代码证据。真正的逐按钮回归仍需要可操作的 Simulator UI channel；在该条件补齐前，不建议把本轮标为完整验收通过。
